# 消息模板配置问题排查指南

## 一、常见错误

### 错误信息

```
未找到当前租户配置的模板类型【site】指定的模板【TPL_SITE_NOTIFY】！
```

### 错误原因

1. **模板未在数据库中配置**
2. **模板ID拼写错误**
3. **租户编码（TENANT_CODE）不匹配**
4. **模板状态不是 valid**

---

## 二、快速解决

### 方案1：插入默认模板（推荐）⭐

执行以下SQL创建默认的站内消息模板：

```sql
-- 1. 先查看你的租户编码
SELECT TENANT_CODE, TENANT_NAME FROM TB_TENANT;

-- 2. 使用正确的租户编码插入模板
INSERT INTO TB_MESSAGE_TEMPLATE (
    ID,
    TEMPLATE_ID,
    TEMPLATE_NAME,
    TEMPLATE_TYPE,
    DETAIL_TYPE,
    TEMPLATE_CONTENT,
    TEMPLATE_STATUS,
    TENANT_CODE,
    CREATE_TIME,
    UPDATE_TIME
) VALUES (
    1000000001,  -- 确保ID不冲突
    'TPL_SITE_NOTIFY',
    '默认站内通知',
    'site',
    'site_notify',
    '{title}\n{content}',
    'valid',
    'default',  -- ⚠️ 改成你的实际租户编码
    NOW(),
    NOW()
);
```

### 方案2：清除缓存后重试

如果模板已存在但仍然报错，可能是Redis缓存问题：

```bash
# 清除模板缓存
redis-cli DEL "MESSAGE_TEMPLATE:site"
redis-cli DEL "MESSAGE_TEMPLATE:wcp"
redis-cli DEL "MESSAGE_TEMPLATE:mobile"
redis-cli DEL "MESSAGE_TEMPLATE:email"

# 或者重启服务
```

### 方案3：修改代码，不使用固定模板ID

已经修改了 `NotificationUtil.sendSiteMessage()` 方法，简单文本消息不再设置 `templateId`，避免模板查找失败。

## 三、详细排查步骤

### 步骤1：检查模板是否存在

```sql
-- 查询所有站内消息模板
SELECT 
    ID,
    TEMPLATE_ID,
    TEMPLATE_NAME,
    TEMPLATE_TYPE,
    DETAIL_TYPE,
    TEMPLATE_STATUS,
    TENANT_CODE
FROM TB_MESSAGE_TEMPLATE
WHERE TEMPLATE_TYPE = 'site';
```

**期望结果：** 应该能看到 `TPL_SITE_NOTIFY` 的记录

**如果没有记录：** 执行方案1的INSERT语句

---

### 步骤2：检查租户编码是否匹配

```sql
-- 查看当前系统的租户配置
SELECT * FROM TB_TENANT;

-- 查看模板的租户编码
SELECT DISTINCT TENANT_CODE FROM TB_MESSAGE_TEMPLATE;
```

**确保：** 模板的 `TENANT_CODE` 与你当前使用的租户一致

**如果不一致：** 
- 修改模板的 `TENANT_CODE`
- 或者插入一条新记录，使用正确的 `TENANT_CODE`

```sql
UPDATE TB_MESSAGE_TEMPLATE 
SET TENANT_CODE = 'your_tenant_code'  -- 改成你的租户编码
WHERE TEMPLATE_ID = 'TPL_SITE_NOTIFY';
```

---

### 步骤3：检查模板状态

```sql
-- 查看模板状态
SELECT TEMPLATE_ID, TEMPLATE_STATUS 
FROM TB_MESSAGE_TEMPLATE 
WHERE TEMPLATE_ID = 'TPL_SITE_NOTIFY';
```

**期望值：** `TEMPLATE_STATUS = 'valid'`

**如果不是 valid：**

```sql
UPDATE TB_MESSAGE_TEMPLATE 
SET TEMPLATE_STATUS = 'valid' 
WHERE TEMPLATE_ID = 'TPL_SITE_NOTIFY';
```

---

### 步骤4：检查Redis缓存

```bash
# 连接Redis
redis-cli

# 查看模板缓存
KEYS MESSAGE_TEMPLATE:*

# 查看具体类型的缓存
GET MESSAGE_TEMPLATE:site

# 如果缓存为空或过期，清除后重新加载
DEL MESSAGE_TEMPLATE:site
```

**说明：**
- 框架启动时会将模板加载到Redis
- 修改数据库后需要清除缓存或重启服务

## 五、NotificationUtil 使用说明

### 5.1 简单文本消息（不需要模板）

```java
// ✅ 推荐：简单文本，不依赖模板
notificationUtil.sendSiteMessage(1001L, "通知标题", "通知内容");
```

**特点：**
- 不设置 `templateId`
- 不会查找模板
- 直接发送 `title` 和 `content`
- 适合临时通知、测试等场景

---

### 5.2 使用模板发送消息

```java
// ✅ 推荐：使用模板，需要先配置模板
Map<String, Object> params = new LinkedHashMap<>();
params.put("orderNo", "ORD20260417001");
params.put("amount", "999.00");

notificationUtil.sendMessageAuto(
    1001L,                      // 用户ID
    "TPL_ORDER_NOTIFY",         // 模板ID（必须存在）
    params                      // 模板参数
);
```

**前提条件：**
- 数据库中必须存在 `TPL_ORDER_NOTIFY` 模板
- 模板的 `TENANT_CODE` 与当前租户匹配
- 模板状态为 `valid`

---

### 5.3 如何选择？

| 场景 | 推荐方法 | 是否需要模板 |
|------|---------|-------------|
| 临时通知、测试 | `sendSiteMessage()` | ❌ 不需要 |
| 正式业务通知 | `sendMessageAuto()` | ✅ 需要 |
| 批量发送 | `sendMessageSmart()` | ✅ 需要 |
| 企业微信 | `sendWechatMessageAuto()` | ✅ 需要 |

## 六、常见问题 FAQ

### Q1: 如何知道我的租户编码是什么？

```sql
-- 查看当前登录用户的租户
SELECT t.TENANT_CODE, t.TENANT_NAME
FROM TB_TENANT t
JOIN TB_USER u ON t.ID = u.TENANT_ID
WHERE u.USER_CODE = 'your_user_code';

-- 或者直接查看所有租户
SELECT * FROM TB_TENANT;
```

---

### Q2: 模板配置后多久生效？

**回答：**
- 框架启动时加载模板到Redis
- 修改数据库后需要：
  1. 清除Redis缓存：`DEL MESSAGE_TEMPLATE:site`
  2. 或者重启服务

---

### Q3: 不同租户可以有相同的模板ID吗？

**可以！** 通过 `TENANT_CODE` 隔离：

```sql
-- 租户A的模板
INSERT INTO TB_MESSAGE_TEMPLATE (...) VALUES (..., 'tenant_a');

-- 租户B的模板（相同的TEMPLATE_ID）
INSERT INTO TB_MESSAGE_TEMPLATE (...) VALUES (..., 'tenant_b');
```

框架会根据当前租户上下文自动加载对应的模板。

---

### Q4: 模板中的占位符怎么写？

使用 Freemarker 语法：

```sql
-- 简单变量
TEMPLATE_CONTENT: '您好，{userName}！'

-- 条件判断
TEMPLATE_CONTENT: '<#if amount > 1000>大额订单<#else>普通订单</#if>'

-- 列表遍历
TEMPLATE_CONTENT: '<#list items as item>${item.name}</#list>'
```

---

### Q5: 为什么有时候报错，有时候不报错？

**可能原因：**
1. **缓存不一致** - 某些节点有缓存，某些没有
2. **租户切换** - 不同租户的模板配置不同
3. **模板被删除或禁用** - 状态改为 `invalid`

**解决方法：**
- 统一清除所有节点的Redis缓存
- 确认当前租户的模板配置
- 检查模板状态
