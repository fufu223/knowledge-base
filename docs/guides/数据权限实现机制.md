# 数据权限实现机制文档

## 一、概述

数据权限是系统中用于控制用户**能查看哪些数据**的机制，与 URI 权限（能否访问某个接口）不同，数据权限实现的是**行级数据访问控制**。

### 1.1 核心设计理念

- **URI 权限**：控制用户能否访问某个接口（如 `/order/list`）
- **数据权限**：控制用户在该接口中能查到哪些数据（如只能查自己创建的订单）

### 1.2 技术实现方案

采用 **AOP 拦截器 + 动态查询条件注入** 的方式：
1. 通过 AOP 拦截所有 `list` 查询接口
2. 根据用户角色动态注入数据过滤条件
3. 在执行 SQL 查询时自动添加 WHERE 条件

---

## 二、架构设计

### 2.1 整体流程

```
用户请求 list 接口
    ↓
ResourcePermissionInterceptor (AOP拦截)
    ↓
DataPermissionsHandler.setCurrentUserDataPermissions()
    ↓
从缓存获取用户的数据权限规则
    ↓
将权限规则转换为 QueryCondition
    ↓
注入到 QueryParameter 中
    ↓
执行查询时自动添加权限过滤条件
    ↓
返回过滤后的数据
```

### 2.2 核心组件

| 组件 | 位置 | 作用 |
|------|------|------|
| **ResourcePermissionInterceptor** | `fastsun-base/src/main/java/com/fastsun/platform/core/component/ResourcePermissionInterceptor.java` | AOP 拦截器，拦截 list 方法 |
| **DataPermissionsHandler** | `fastsun-base/src/main/java/com/fastsun/platform/core/component/DataPermissionsHandler.java` | 数据权限处理器，转换权限规则 |
| **IResourcePermissionHandler** | `fastsun-base/src/main/java/com/fastsun/platform/core/component/component/IResourcePermissionHandler.java` | 动态值处理器接口 |
| **AbstractFastsunDtoService** | `fastsun-base/src/main/java/com/fastsun/platform/core/service/impl/AbstractFastsunDtoService.java` | Service 层，执行查询并应用条件 |

## 三、数据模型

### 3.1 资源权限表（TB_RESOURCE_PERMISSION）

存储数据权限规则配置。

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| id | Long | 主键 | 1 |
| code | String | 资源编码 | `my_resource` |
| name | String | 资源名称 | `我的数据权限` |
| voList | String | 适用的 VO 列表（逗号分隔） | `base_user,base_order` |
| scripts | String | 权限规则（JSON 格式） | 见下方示例 |

### 3.2 角色资源关联表（TB_ROLE_RESOURCE）

将数据权限规则关联到角色。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | 主键 |
| roleId | Long | 角色 ID |
| resourceId | Long | 资源 ID |
| resourceCode | String | 资源编码 |
| resourceName | String | 资源名称 |
| voList | String | VO 列表 |
| scripts | String | 权限规则 |

### 3.3 权限规则 scripts 格式

#### **格式 1：单个条件（JSON 对象）**

```json
{
  "field": "createUserId",
  "operator": "eq",
  "value": "@@CurrentUserId",
  "andOr": "and"
}
```

#### **格式 2：多个条件（JSON 数组）**

```json
[
  {
    "field": "orgId",
    "operator": "in",
    "value": "@@CurrentOrgIds",
    "andOr": "and"
  },
  {
    "field": "createUserId",
    "operator": "eq",
    "value": "@@CurrentUserId",
    "andOr": "or"
  }
]
```

#### **格式 3：特殊值**

| field | value | 含义 |
|-------|-------|------|
| `1` | `1` | 查看全部数据 |
| `1` | `0` | 禁止访问任何数据 |

## 四、核心实现

### 4.1 AOP 拦截器

**文件位置**：`ResourcePermissionInterceptor.java`

```java
@Aspect
@Component
@ConditionalOnProperty(
    prefix = "fastsun.platform.resource.permission",
    name = "enable",
    havingValue = "true",
    matchIfMissing = false)
public class ResourcePermissionInterceptor {
    
    @Autowired
    private DataPermissionsHandler dataPermissionsHandler;

    /**
     * 拦截所有 Controller 的 list 方法
     */
    @Pointcut("execution(public * com.fastsun..*.*Controller.list(..))")
    public void pointCut() {
    }

    @Before("pointCut()")
    public void addResourcePermission(JoinPoint joinPoint) {
        HttpServletRequest request = ((ServletRequestAttributes) 
            RequestContextHolder.getRequestAttributes()).getRequest();
        
        // 1. 获取 voCode（模型编码）
        String voCode = request.getParameter("vo");
        if (ObjectUtils.isEmpty(voCode)) {
            String[] paths = request.getServletPath().split("/");
            voCode = paths[1];  // 从 URL 路径获取，如 /base/list → base
        }
        
        // 2. 获取查询参数
        Object[] args = joinPoint.getArgs();
        if (args.length != 6 || !(args[5] instanceof QueryParameter)) {
            return;
        }
        QueryParameter param = (QueryParameter) args[5];
        
        // 3. 注入数据权限条件
        dataPermissionsHandler.setCurrentUserDataPermissions(voCode, param);
    }
}
```

**关键点**：
- 使用 `@ConditionalOnProperty` 控制是否启用数据权限
- 拦截点：`execution(public * com.fastsun..*.*Controller.list(..))`
- 从请求参数或 URL 路径获取 voCode
- 在方法执行前（`@Before`）注入权限条件

### 4.2 数据权限处理器

**文件位置**：`DataPermissionsHandler.java`

```java
@Component
public class DataPermissionsHandler {

    @Autowired
    private ICacheService cacheService;

    /**
     * 设置当前用户的数据权限
     */
    public void setCurrentUserDataPermissions(String voCode, QueryParameter parameter) {
        TenantDTO tenant = LocalTenantContext.get();
        UserDTO baseUser = LocalUserContext.get();
        
        if (baseUser == null) {
            return;
        }
        
        // 1. 从缓存获取用户的数据权限配置
        List<RoleResourceDTO> resources = (List<RoleResourceDTO>) cacheService.getMapValue(
            TENANT_USER_RESOURCE_CACHE_KEY + tenant.getId(), 
            String.valueOf(baseUser.getId())
        );
        
        if (resources == null) {
            return;
        }
        
        // 2. 过滤出当前 VO 的权限规则
        List<RoleResourceDTO> resourceList = resources.stream()
            .filter(o -> !ObjectUtils.isEmpty(o.getVoList())
                    && Arrays.asList(o.getVoList().split(",")).contains(voCode)
                    && !ObjectUtils.isEmpty(o.getScripts()))
            .collect(Collectors.toList());
        
        // 3. 如果没有配置权限规则
        if (resourceList.size() <= 0) {
            // 检查资源权限表中是否有该 VO 的配置
            List<ResourceDTO> alls = cacheService.getMapValue(
                TENANT_RESOURCE_CACHE_KEY, tenant.getTenantCode());
            
            Optional<ResourceDTO> first = alls.stream()
                .filter(o -> Arrays.asList(o.getVoList().split(",")).contains(voCode))
                .findFirst();
            
            if (first.isPresent()) {
                // 配置了但没有权限，返回 1=0 条件（查不到数据）
                QueryCondition build = QueryCondition.builder()
                    .field("1")
                    .operator("eq")
                    .value("0")
                    .andOr("and")
                    .build();
                parameter.setQueryConditions(Collections.singletonList(build));
            }
            return;
        }
        
        // 4. 检查是否有"查看全部"权限（field="1", value="1"）
        boolean hasAll = resourceList.stream()
            .map(o -> JSONUtil.isJsonArray(o.getScripts())
                    ? JsonUtils.readValue(o.getScripts(), QueryCondition.class)
                    : Collections.singletonList(JsonUtils.readSingleValue(o.getScripts(), QueryCondition.class)))
            .flatMap(Collection::stream)
            .anyMatch(o -> Objects.equals(o.getField(), "1") && Objects.equals(o.getValue(), "1"));
        
        if (hasAll) {
            return;  // 有全部权限，不添加过滤
        }
        
        // 5. 将 scripts 转换为 QueryCondition
        List<QueryCondition> newConditions = new ArrayList<>();
        for (int i = 0; i < resourceList.size(); i++) {
            RoleResourceDTO o = resourceList.get(i);
            if (!o.getVoList().contains(voCode)) {
                continue;
            }
            
            String scripts = o.getScripts();
            if (JSONUtil.isJsonObj(scripts)) {
                newConditions.add(getCondition(new JSONObject(scripts)));
                newConditions.add(QueryCondition.builder()
                    .andOr("or")
                    .subCondition(new ArrayList<>())
                    .build());
            } else if (JSONUtil.isJsonArray(scripts)) {
                JSONArray jarr = new JSONArray(scripts);
                jarr.forEach(obj -> {
                    newConditions.add(getCondition((JSONObject) obj));
                });
            }
            
            // 多个资源规则之间用 OR 连接
            if (i < resourceList.size() - 1) {
                QueryCondition last = newConditions.get(newConditions.size() - 1);
                if (!ObjectUtils.isEmpty(last.getField())) {
                    newConditions.add(QueryCondition.builder()
                        .andOr("or")
                        .subCondition(new ArrayList<>())
                        .build());
                }
            }
        }
        
        // 6. 将权限条件注入到查询参数中
        if (!CollectionUtils.isEmpty(newConditions)) {
            QueryCondition permCondition = QueryCondition.builder()
                .andOr("or")
                .subCondition(newConditions)
                .build();
            
            List<QueryCondition> oldConditions = parameter.getQueryConditions();
            if (!CollectionUtils.isEmpty(oldConditions)) {
                // 合并原有查询条件（AND 关系）
                QueryCondition logicCondition = QueryCondition.builder()
                    .andOr("and")
                    .subCondition(new ArrayList<>())
                    .build();
                QueryCondition oldCondition = QueryCondition.builder()
                    .subCondition(oldConditions)
                    .build();
                parameter.setQueryConditions(Arrays.asList(permCondition, logicCondition, oldCondition));
            } else {
                parameter.setQueryConditions(Collections.singletonList(permCondition));
            }
        }
    }
    
    /**
     * 解析 JSON 为 QueryCondition
     */
    private QueryCondition getCondition(JSONObject json) {
        QueryCondition permCondition = new QueryCondition();
        permCondition.setAndOr(json.getStr("andOr"));
        permCondition.setField(json.getStr("field"));
        permCondition.setOperator(json.getStr("operator"));
        permCondition.setValue(json.get("value"));
        permCondition.setSubCondition(new ArrayList<>());
        converterValue(permCondition);  // 处理动态值
        return permCondition;
    }
    
    /**
     * 处理动态值（如 @@CurrentUserId）
     */
    private void converterValue(QueryCondition condition) {
        String value = (String) condition.getValue();
        if (StringUtils.hasLength(value) && value.startsWith("@@")) {
            String beanName = value.substring(2) + "Resource";  // @@CurrentUserId → CurrentUserIdResource
            IResourcePermissionHandler bean = ApplicationContextProvider.getBean(
                beanName, IResourcePermissionHandler.class);
            Assert.notNull(bean, "未找到权限串【" + value + "】的处理代码！");
            condition.setValue(bean.getValue(value));  // 动态获取实际值
        }
    }
}
```

### 4.3 动态值处理器

当 scripts 中的 value 以 `@@` 开头时，会调用对应的 Handler 动态获取值。

#### **接口定义**

```java
public interface IResourcePermissionHandler {
    Object getValue(String value);
}
```

#### **内置处理器**

| Bean 名称 | 类 | 返回值 | 说明 |
|-----------|---|--------|------|
| `CurrentUserIdResource` | `CurrentUserIdResourcePermissionHandler` | 当前用户 ID | 只能查看自己的数据 |
| `CurrentUserNameResource` | `CurrentUsernameResourcePermissionHandler` | 当前用户名 | 按用户名过滤 |
| `CurrentOrgIdResource` | `CurrentOrganIdResourcePermissionHandler` | 当前组织 ID | 只能查看当前组织的数据 |
| `CurrentOrgIdsResource` | `CurrentOrgIdsResourcePermissionHandler` | 当前用户所有组织 ID 列表 | 查看所属组织的数据 |
| `SuperOrgIdsResource` | `SuperOrgIdsResourcePermissionHandler` | 当前组织及下级组织 ID 列表 | 查看本组织及下级组织的数据 |

**示例：CurrentUserIdResourcePermissionHandler**

```java
@Component("CurrentUserIdResource")
public class CurrentUserIdResourcePermissionHandler implements IResourcePermissionHandler {
    @Override
    public Object getValue(String value) {
        UserDTO userDTO = LocalUserContext.get();
        return String.valueOf(userDTO.getId());
    }
}
```

### 4.4 查询条件应用

**文件位置**：`AbstractFastsunDtoService.java`

```java
public FastsunPage<D> findPageByQuery(QueryParameter query) {
    beforeQuery(query);
    
    // 分页参数处理
    PageParameter pageParameter = query.getPageParameter();
    if (ObjectUtils.isEmpty(pageParameter)) {
        pageParameter = new PageParameter();
        pageParameter.setPageIndex(1);
        pageParameter.setPageSize(20);
        query.setPageParameter(pageParameter);
    }
    
    Sort sort = toSort(query);
    FastsunBaseRepository repository = (FastsunBaseRepository) getRepository();
    
    // 关键：创建 Specification，将 QueryParameter 转换为 JPA Predicate
    Specification<T> specification = (root, cq, cb) -> toPredicate(query, root, cq, cb);
    
    // 执行查询，Specification 会自动生成 WHERE 条件
    PageRequest pageRequest = PageRequest.of(
        pageParameter.getPageIndex() - 1,
        pageParameter.getPageSize(),
        sort == null ? Sort.unsorted() : sort);
    Page<T> page = repository.findAll(specification, pageRequest);
    
    return fastsunPage;
}

/**
 * 将 QueryParameter 转换为 JPA Predicate
 */
protected Predicate toPredicate(QueryParameter queryParameter,
                                Root<T> root,
                                CriteriaQuery<?> cq,
                                CriteriaBuilder cb) {
    if (queryParameter != null && queryParameter.getQueryConditions() != null) {
        List<QueryCondition> queryConditions = queryParameter.getQueryConditions();
        Map<String, Join> joinMap = new HashMap<>();
        
        // 处理 JOIN 条件
        queryConditions.stream()
            .filter(o -> Objects.equals(o.getType(), "object"))
            .collect(Collectors.toList())
            .forEach(o -> {
                String[] fields = o.getField().split("\\.");
                joinMap.put(o.getField(), root.join(fields[0], JoinType.LEFT));
            });
        
        // 处理所有查询条件（包括数据权限条件）
        Predicate predicate = handleCondition(root, cb, queryConditions, joinMap, null);
        
        return predicate;  // 返回的 Predicate 会作为 WHERE 条件
    }
    return null;
}
```

## 五、使用示例

### 5.1 场景 1：只能查看自己创建的数据

**配置 scripts：**
```json
{
  "field": "createUserId",
  "operator": "eq",
  "value": "@@CurrentUserId",
  "andOr": "and"
}
```

**执行时转换为：**
```sql
WHERE createUserId = 123  -- 123 是当前用户 ID
```

### 5.2 场景 2：可以查看本组织的数据

**配置 scripts：**
```json
{
  "field": "orgId",
  "operator": "in",
  "value": "@@CurrentOrgIds",
  "andOr": "and"
}
```

**执行时转换为：**
```sql
WHERE orgId IN (10, 11, 12)  -- 当前用户所属的组织 ID 列表
```

### 5.3 场景 3：可以查看自己创建的或本组织的数据

**配置 scripts：**
```json
[
  {
    "field": "orgId",
    "operator": "in",
    "value": "@@CurrentOrgIds",
    "andOr": "and"
  },
  {
    "field": "createUserId",
    "operator": "eq",
    "value": "@@CurrentUserId",
    "andOr": "or"
  }
]
```

**执行时转换为：**
```sql
WHERE orgId IN (10, 11, 12) OR createUserId = 123
```

### 5.4 场景 4：查看本组织及下级组织的数据

**配置 scripts：**
```json
{
  "field": "orgId",
  "operator": "in",
  "value": "@@SuperOrgIds",
  "andOr": "and"
}
```

**说明：** `@@SuperOrgIds` 会被 `SuperOrgIdsResourcePermissionHandler` 处理，返回当前组织及其所有下级组织的 ID 列表。

### 5.5 场景 5：查看全部数据

**配置 scripts：**
```json
{
  "field": "1",
  "operator": "eq",
  "value": "1",
  "andOr": "and"
}
```

**说明：** 当检测到 `field="1"` 且 `value="1"` 时，不添加任何过滤条件，用户可以查看所有数据。

### 5.6 场景 6：禁止访问任何数据

**配置 scripts：**
```json
{
  "field": "1",
  "operator": "eq",
  "value": "0",
  "andOr": "and"
}
```

**执行时转换为：**
```sql
WHERE 1 = 0  -- 永远为 false，查不到数据
```

## 六、查询条件合并逻辑

### 6.1 合并规则

最终生成的查询结构：

```
(权限条件1 OR 权限条件2 OR ...) AND (原有查询条件1 AND 原有查询条件2 AND ...)
```

### 6.2 实际示例

**用户输入查询条件：**
- status = 'active'
- name LIKE '%测试%'

**数据权限规则：**
- orgId IN (10, 11) OR createUserId = 123

**最终生成的 SQL：**
```sql
SELECT * FROM table_name 
WHERE (orgId IN (10, 11) OR createUserId = 123) 
  AND (status = 'active' AND name LIKE '%测试%')
ORDER BY createTime DESC
LIMIT 20 OFFSET 0
```

## 七、缓存机制

### 7.1 缓存结构

用户的数据权限缓存在 Redis 中：

- **Key**: `TENANT_USER_RESOURCE_CACHE_KEY + tenantId`
- **Field**: `userId`
- **Value**: `List<RoleResourceDTO>`

### 7.2 缓存刷新时机

缓存在以下情况刷新：
1. 角色权限变更时
2. 用户角色变更时
3. 资源权限规则修改时

### 7.3 缓存代码示例

**设置缓存：**
```java
cache.setMapValue(
    TENANT_USER_RESOURCE_CACHE_KEY + tenant.getId(), 
    String.valueOf(user.getId()), 
    resources
);
```

**获取缓存：**
```java
List<RoleResourceDTO> resources = (List<RoleResourceDTO>) cache.getMapValue(
    TENANT_USER_RESOURCE_CACHE_KEY + tenant.getId(), 
    String.valueOf(baseUser.getId())
);
```

## 九、常见问题

### 9.1 数据权限不生效？

**检查清单：**
1. 确认 `fastsun.platform.resource.permission.enable=true`
2. 确认用户已分配包含数据权限规则的角色
3. 确认缓存中已有用户权限数据
4. 检查 voCode 是否正确（与 VO 编码一致）
5. 查看日志输出，确认权限条件已注入

### 9.2 如何自定义动态值处理器？

**步骤：**

1. 实现 `IResourcePermissionHandler` 接口：

```java
@Component("MyCustomResource")  // Bean 名称为：自定义名称 + "Resource"
public class MyCustomResourcePermissionHandler implements IResourcePermissionHandler {
    @Override
    public Object getValue(String value) {
        // 返回动态值
        return "your_value";
    }
}
```

2. 在 scripts 中使用：

```json
{
  "field": "customField",
  "operator": "eq",
  "value": "@@MyCustom",  // 会调用 MyCustomResource handler
  "andOr": "and"
}
```

### 9.3 如何调试数据权限？

**开启调试日志：**

```yaml
logging:
  level:
    com.fastsun.platform.core.component.DataPermissionsHandler: DEBUG
```

**查看日志输出：**
```
当前VO base_order，数据权限为：[{"voList":"base_order","scripts":"..."}]
{"queryConditions":[...]}
```

## 十、总结

### 10.1 核心优势

1. **透明拦截**：对业务代码无侵入，自动注入权限条件
2. **灵活配置**：通过 JSON 配置权限规则，支持复杂条件组合
3. **动态解析**：支持 `@@` 动态值，实时获取用户上下文
4. **高性能**：使用 Redis 缓存权限数据，避免频繁查询数据库
5. **可扩展**：可自定义动态值处理器，满足特殊业务需求

### 10.2 关键设计

- **AOP 拦截**：在 Controller 层拦截，确保所有 list 查询都经过权限过滤
- **条件注入**：将权限规则转换为 QueryCondition，注入到 QueryParameter
- **JPA Specification**：利用 JPA 动态查询能力，将条件转换为 SQL WHERE 子句
- **缓存优化**：Redis 缓存用户权限数据，提升查询性能

### 10.3 适用场景

- 按用户过滤：只能查看自己创建的数据
- 按组织过滤：只能查看本组织的数据
- 按角色过滤：不同角色看到不同范围的数据
- 复杂组合：支持多条件 OR/AND 组合
