# H5端静态资源路径问题说明

## 一、问题现象

### 1.1 访问对比

**Web端（正常）：**
```
HTML: http://localhost:10222/hnsh/web/index.html
JS:   http://localhost:10222/hnsh/web/static/js/app.xxx.js  ✅ 正确
CSS:  http://localhost:10222/hnsh/web/static/css/style.css  ✅ 正确
```

**H5端（异常）：**
```
HTML: http://localhost:10222/hnsh/h5/index.html              ✅ 正确
JS:   http://localhost:10222/assets/index-C8vi-olr.js        ❌ 错误
CSS:  http://localhost:10222/assets/index-xxx.css            ❌ 错误
```

### 1.2 错误原因

H5端的 JS/CSS 资源路径是 `/assets/xxx`，而不是 `/hnsh/h5/assets/xxx`。

这导致：
1. **404错误**：Spring Boot 的 ResourceHandler 只处理 `/h5/**` 路径
2. **资源加载失败**：浏览器无法找到 JS/CSS 文件

---

## 二、根本原因

### 2.1 不是打包工具的问题

虽然 Web 端用 Webpack，H5 端用 Vite，但**问题的本质不是打包工具的差异**，而是 **`publicPath` / `base` 配置不同**。

### 2.2 Vite 的 `base` 配置

在 `vite.config.js` 中：

```javascript
export default defineConfig({
  base: '/'  // ← 问题在这里！
})
```

**`base: '/'` 的效果：**
- 所有资源路径从网站根目录开始
- `<script src="/assets/app.js">` 
- 浏览器解析为：`http://localhost:10222/assets/app.js`

**应该改为：**
```javascript
export default defineConfig({
  base: './'  // 相对路径
  // 或者
  base: '/hnsh/h5/'  // 绝对路径（需要动态配置）
})
```

### 2.3 Webpack 的 `publicPath` 配置

在 `vue.config.js` 中：

```javascript
module.exports = {
  publicPath: './'  // Web端配置正确
}
```

**`publicPath: './'` 的效果：**
- 使用相对路径
- `<script src="./static/js/app.js">`
- 浏览器解析为：`http://localhost:10222/hnsh/web/static/js/app.js` ✅

---

## 三、解决方案

### 方案一：修改 Vite 配置为相对路径（✅ 推荐）

**适用场景：** 应用部署路径不固定，需要灵活性

#### 步骤1：修改 vite.config.js

```javascript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  base: './',  // 使用相对路径
  build: {
    outDir: 'dist_h5',
    assetsDir: 'assets'
  }
})
```

#### 步骤2：重新打包

```bash
npm run build
```

#### 步骤3：验证

生成的 `index.html` 应该是：
```html
<!DOCTYPE html>
<html>
<head>
  <link rel="stylesheet" href="./assets/index-xxx.css">
</head>
<body>
  <div id="app"></div>
  <script type="module" src="./assets/index-C8vi-olr.js"></script>
</body>
</html>
```

浏览器解析后：
```
http://localhost:10222/hnsh/h5/assets/index-C8vi-olr.js  ✅
```

---

### 方案二：修改 Vite 配置为动态路径（✅ 推荐用于多租户）

**适用场景：** 不同租户有不同的应用编码，需要动态配置

#### 步骤1：使用环境变量

```javascript
// vite.config.js
import { defineConfig, loadEnv } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd())
  
  return {
    plugins: [vue()],
    base: env.VITE_APP_BASE_PATH || './',  // 从环境变量读取
    build: {
      outDir: 'dist_h5',
      assetsDir: 'assets'
    }
  }
})
```

#### 步骤2：创建环境变量文件

**.env.production**
```env
VITE_APP_BASE_PATH=/hnsh/h5/
```

**.env.development**
```env
VITE_APP_BASE_PATH=/hnsh/h5/
```

#### 步骤3：打包时指定环境

```bash
npm run build -- --mode production
```

### 方案三：后端添加额外的 ResourceHandler（临时方案）

如果暂时无法修改前端配置，可以在后端添加通配符匹配。

#### 修改 LowCodeWebMvcConfig.java

```java
@Override
public void addResourceHandlers(ResourceHandlerRegistry registry) {
    String appId = applicationName;
    if (CharSequenceUtil.endWith(applicationName, "s")) {
        appId = CharSequenceUtil.removeSuffix(applicationName, "s");
    }
    String appRootPath = "/opt/lowcode/0/core/" + appId;
    String distWebPath = appRootPath + File.separator + "dist" + File.separator + "dist_web" + File.separator;
    String distH5Path = appRootPath + File.separator + "dist" + File.separator + "dist_h5" + File.separator;
    String prefix = "file:";
    if (System.getProperty("os.name").toLowerCase().contains("windows")) {
        prefix = "file:///";
    }
    String webPath = prefix + distWebPath;
    String h5Path = prefix + distH5Path;

    // 原有配置
    registry.addResourceHandler("/web/**").addResourceLocations(webPath);
    registry.addResourceHandler("/h5/**").addResourceLocations(h5Path);
    
    // 新增：处理 H5 的 /assets/ 路径
    registry.addResourceHandler("/assets/**")
            .addResourceLocations(h5Path + "assets" + File.separator);
}
```

**缺点：**
- ⚠️ 如果有多个应用，会冲突
- ⚠️ 治标不治本
- ⚠️ 不推荐生产环境使用

### 方案四：Nginx 重写规则（生产环境推荐）

如果使用 Nginx 作为反向代理：

```nginx
server {
    listen 80;
    server_name dev.bgcinfo.net;

    # H5端
    location /hnsh/h5/ {
        alias /opt/lowcode/hnsh/dist/dist_h5/;
        try_files $uri $uri/ /hnsh/h5/index.html;
    }
    
    # 处理 /assets/ 路径
    location /assets/ {
        alias /opt/lowcode/hnsh/dist/dist_h5/assets/;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
    
    # API 请求转发
    location /hnsh/api/ {
        proxy_pass http://localhost:10222/hnsh/;
    }
}
```

## 四、最佳实践

### 4.1 开发环境

```javascript
// vite.config.js
export default defineConfig({
  base: './',  // 开发时使用相对路径
  server: {
    port: 3000,
    proxy: {
      '/api': 'http://localhost:10222'
    }
  }
})
```

### 4.2 生产环境

```javascript
// vite.config.js
import { defineConfig, loadEnv } from 'vite'

export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd())
  
  return {
    base: env.VITE_APP_BASE_PATH || './',
    build: {
      outDir: 'dist_h5',
      assetsDir: 'assets',
      rollupOptions: {
        output: {
          // 自定义文件名，避免缓存问题
          entryFileNames: 'assets/[name]-[hash].js',
          chunkFileNames: 'assets/[name]-[hash].js',
          assetFileNames: 'assets/[name]-[hash].[ext]'
        }
      }
    }
  }
})
```

### 4.3 多租户动态配置

在前端应用中，可以通过运行时配置动态设置 `base`：

```javascript
// src/config.js
const getAppBasePath = () => {
  // 从 URL 或配置文件获取
  const pathSegments = window.location.pathname.split('/')
  // 假设 URL 是 /hnsh/h5/index.html
  // 提取出 /hnsh/h5/
  if (pathSegments.length >= 3) {
    return `/${pathSegments[1]}/${pathSegments[2]}/`
  }
  return './'
}

export const APP_BASE_PATH = getAppBasePath()
```

然后在 HTML 中使用：

```html
<!DOCTYPE html>
<html>
<head>
  <script>
    window.APP_BASE_PATH = '/hnsh/h5/'
  </script>
</head>
<body>
  <div id="app"></div>
  <script type="module">
    const basePath = window.APP_BASE_PATH
    const script = document.createElement('script')
    script.type = 'module'
    script.src = basePath + 'assets/index.js'
    document.body.appendChild(script)
  </script>
</body>
</html>
```

## 六、常见问题

### Q1: 为什么 Web 端没问题？

**A:** Web 端的 Webpack 配置中 `publicPath: './'` 使用了相对路径，所以资源路径是正确的。

### Q2: 必须用相对路径吗？

**A:** 不一定。也可以使用绝对路径，但需要确保路径与应用的实际部署路径一致：
- 单租户：`base: '/hnsh/h5/'`
- 多租户：需要动态配置

### Q3: 相对路径和绝对路径有什么区别？

| 特性 | 相对路径 (`./`) | 绝对路径 (`/hnsh/h5/`) |
|------|----------------|----------------------|
| 灵活性 | ✅ 高，可部署到任意路径 | ❌ 低，路径固定 |
| 配置复杂度 | ✅ 简单 | ❌ 需要知道完整路径 |
| CDN支持 | ❌ 不支持 | ✅ 支持 |
| 多租户 | ✅ 天然支持 | ❌ 需要动态配置 |

### Q4: 如何在运行时动态修改 base？

**A:** Vite 不支持运行时修改 `base`，但可以通过以下方式实现：
1. 使用 HTML 中的 `<base>` 标签
2. 手动拼接资源路径
3. 使用 Nginx 重写规则

### Q5: 修改配置后需要重新打包吗？

**A:** 是的，`base` 配置是在打包时生效的，修改后必须重新执行 `npm run build`。

## 七、总结

### 7.1 核心要点

1. **问题根源**：Vite 的 `base` 配置为 `/`，导致资源路径从根目录开始
2. **不是打包工具的问题**：Webpack 和 Vite 都可以正确配置
3. **推荐方案**：使用相对路径 `base: './'`
4. **多租户场景**：使用环境变量动态配置

### 7.2 快速修复

```javascript
// vite.config.js
export default defineConfig({
  base: './',  // 改这一行
  build: {
    outDir: 'dist_h5'
  }
})
```

然后重新打包：
```bash
npm run build
```

### 7.3 预防措施

1. **统一配置规范**：Web 和 H5 都使用相对路径
2. **CI/CD 检查**：打包后自动检查资源路径
3. **自动化测试**：验证资源能否正确加载
4. **文档化**：记录配置要求和注意事项
