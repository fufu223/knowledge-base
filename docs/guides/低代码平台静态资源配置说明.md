# 低代码平台静态资源配置说明文档

## 一、概述

本文档详细说明 fastsun-platform 低代码平台中前端静态资源（Web端和H5端）的配置机制、作用原理及代码实现过程。

---

## 二、配置说明

### 2.1 核心配置项

#### 2.1.1 defaultAppRootPath（应用根路径）

**配置位置：** `application.yml` 或 `bootstrap.yml`

```yaml
fastsun:
  platform:
    setting:
      defaultAppRootPath: /opt/lowcode  # Linux默认路径
      # defaultAppRootPath: D:/lowcode  # Windows路径示例
```

**配置说明：**
- **配置键：** `fastsun.platform.setting.defaultAppRootPath`
- **默认值：** `/opt/lowcode`
- **作用：** 指定低代码应用部署的根目录路径
- **优先级：** 如果应用中配置了 `appRoot`，则使用应用的自定义路径，否则使用此默认值

#### 2.1.2 静态资源路径结构

根据代码实现，静态资源的完整路径结构为：

```
{defaultAppRootPath}/{appCode}/dist/dist_web/     # Web端静态资源
{defaultAppRootPath}/{appCode}/dist/dist_h5/      # H5端静态资源
```

**示例：**
```
/opt/lowcode/hnsh/dist/dist_web/index.html    # Web端首页
/opt/lowcode/hnsh/dist/dist_h5/index.html     # H5端首页
```

## 三、功能作用

### 3.1 主要功能

1. **静态资源服务**
   - 为低代码应用提供前端页面访问能力
   - 支持 Web 端和 H5 端两种前端形态
   - 通过 Spring MVC 的 ResourceHandler 直接返回静态文件

2. **前后端分离架构支持**
   - 前端打包后的静态文件存储在服务器文件系统
   - 后端 Spring Boot 应用作为静态资源服务器
   - 前端路由采用 Hash 模式（`#/xxx`），无需后端支持

3. **多应用隔离**
   - 每个低代码应用有独立的静态资源目录
   - 通过应用编码（appCode）进行隔离
   - 支持独立部署和模板部署两种模式

### 3.2 访问方式

#### Web端访问
```
http://{host}:{port}/{appCode}/web/index.html
```

**示例：**
```
http://dev.bgcinfo.net:10222/hnsh/web/index.html#/login
```

#### H5端访问
```
http://{host}:{port}/{appCode}/h5/index.html
```

**URL解析：**
- `hnsh`：应用编码（appCode）
- `/web/**`：Spring MVC 静态资源拦截路径
- `index.html`：实际静态文件
- `#/login`：前端路由（Hash路由，不发送到服务器）

## 四、代码实现过程

### 4.1 核心配置类

框架中有两个 WebMvcConfigurer 配置类负责静态资源映射：

#### 4.1.1 LowCodeWebMvcConfig

**文件路径：** 
`fastsun-lowcode-app-domain/src/main/java/com/fastsun/platform/core/lowcode/config/LowCodeWebMvcConfig.java`

**核心代码：**

```java
@Configuration
public class LowCodeWebMvcConfig implements WebMvcConfigurer {

    @Value("${spring.application.name}")
    private String applicationName;

    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        // 1. 处理应用名称（去除末尾的's'）
        String appId = applicationName;
        if (CharSequenceUtil.endWith(applicationName, "s")) {
            appId = CharSequenceUtil.removeSuffix(applicationName, "s");
        }
        
        // 2. 构建应用根路径
        String appRootPath = "/opt/lowcode/0/core/" + appId;
        
        // 3. 构建Web和H5静态资源路径
        String distWebPath = appRootPath + File.separator + "dist" + File.separator + "dist_web" + File.separator;
        String distH5Path = appRootPath + File.separator + "dist" + File.separator + "dist_h5" + File.separator;
        
        // 4. 根据操作系统设置文件协议前缀
        String prefix = "file:";
        if (System.getProperty("os.name").toLowerCase().contains("windows")) {
            prefix = "file:///";
        }
        String webPath = prefix + distWebPath;
        String h5Path = prefix + distH5Path;

        // 5. 注册静态资源处理器
        registry.addResourceHandler("/web/**").addResourceLocations(webPath);
        registry.addResourceHandler("/h5/**").addResourceLocations(h5Path);
    }
}
```

#### 4.1.2 WebMvcConfig

**文件路径：** 
`fastsun-lowcode-code/src/main/java/com/fastsun/platform/core/lowcode/code/config/WebMvcConfig.java`

**核心代码：**

```java
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {

    @Value("${spring.application.name}")
    private String applicationName;

    @Autowired
    private CodeManageService codeManageService;

    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        // 1. 处理应用名称
        String appId = applicationName;
        if (CharSequenceUtil.endWith(applicationName, "s")) {
            appId = CharSequenceUtil.removeSuffix(applicationName, "s");
        }
        
        // 2. 通过服务获取应用根路径
        String appRootPath = codeManageService.getAppRootPath(appId);
        
        // 3. 构建静态资源路径
        String distWebPath = appRootPath + File.separator + "dist" + File.separator + "dist_web" + File.separator;
        String distH5Path = appRootPath + File.separator + "dist" + File.separator + "dist_h5" + File.separator;
        
        // 4. 设置文件协议前缀
        String prefix = "file:";
        if (System.getProperty("os.name").toLowerCase().contains("windows")) {
            prefix = "file:///";
        }
        String webPath = prefix + distWebPath;
        String h5Path = prefix + distH5Path;

        // 5. 注册静态资源处理器
        registry.addResourceHandler("/web/**").addResourceLocations(webPath);
        registry.addResourceHandler("/h5/**").addResourceLocations(h5Path);
        
        System.out.println("注册静态资源完成,webpath:" + webPath);
        System.out.println("注册静态资源完成,h5path:" + h5Path);
    }
}
```

### 4.2 实现流程详解

#### 步骤1：应用名称处理

```java
String appId = applicationName;
if (CharSequenceUtil.endWith(applicationName, "s")) {
    appId = CharSequenceUtil.removeSuffix(applicationName, "s");
}
```

**说明：** 
- Spring Boot 应用名称通常为 `{appCode}s` 格式（如 `hnshs`）
- 需要去除末尾的 `s` 得到实际的应用编码（如 `hnsh`）

#### 步骤2：构建应用根路径

**方式一：硬编码路径（LowCodeWebMvcConfig）**
```java
String appRootPath = "/opt/lowcode/0/core/" + appId;
```

**方式二：动态获取路径（WebMvcConfig）**
```java
String appRootPath = codeManageService.getAppRootPath(appId);
```

#### 步骤3：构建静态资源完整路径

```java
// Web端路径
String distWebPath = appRootPath + File.separator + "dist" + File.separator + "dist_web" + File.separator;

// H5端路径
String distH5Path = appRootPath + File.separator + "dist" + File.separator + "dist_h5" + File.separator;
```

**路径示例（Linux）：**
```
/opt/lowcode/0/core/hnsh/dist/dist_web/
/opt/lowcode/0/core/hnsh/dist/dist_h5/
```

#### 步骤4：设置文件协议前缀

```java
String prefix = "file:";
if (System.getProperty("os.name").toLowerCase().contains("windows")) {
    prefix = "file:///";
}
String webPath = prefix + distWebPath;
String h5Path = prefix + distH5Path;
```

**说明：**
- Linux 系统：`file:/opt/lowcode/...`
- Windows 系统：`file:///D:/lowcode/...`
- 这是 Spring ResourceHandler 要求的文件 URI 格式

#### 步骤5：注册静态资源处理器

```java
registry.addResourceHandler("/web/**").addResourceLocations(webPath);
registry.addResourceHandler("/h5/**").addResourceLocations(h5Path);
```

**说明：**
- `/web/**`：拦截所有以 `/web/` 开头的请求
- `/h5/**`：拦截所有以 `/h5/` 开头的请求
- `addResourceLocations()`：指定实际的物理文件路径

### 4.3 请求处理流程

```
用户浏览器
    ↓
发起请求: http://dev.bgcinfo.net:10222/hnsh/web/index.html
    ↓
Spring MVC DispatcherServlet
    ↓
ResourceHandlerMapping 匹配 /web/** 模式
    ↓
LowCodeWebMvcConfig / WebMvcConfig 注册的处理器
    ↓
读取文件系统: /opt/lowcode/0/core/hnsh/dist/dist_web/index.html
    ↓
返回 HTML 文件内容
    ↓
浏览器解析 HTML，加载 CSS/JS 等资源
    ↓
前端框架根据 #/login 进行路由跳转
```

## 五、安全配置

### 5.1 白名单配置

静态资源路径已被加入安全白名单，无需认证即可访问。

**配置文件：** `fastsun-base/src/main/java/com/fastsun/platform/core/security/SecurityConfigurer.java`

```java
add("/web/*/**");
add("/web/**");
```

**说明：**
- **只有 `/web/**` 路径下的资源可以匿名访问**
- **`/h5/**` 路径默认不在白名单中，需要认证才能访问**
- 这是框架的有意设计，H5端主要面向微信生态，使用OAuth2自动登录
- 如需开放H5端访问，需手动添加白名单配置（见常见问题8.4）

### 5.2 Gateway 层配置

**配置文件：** `fastsun-gateway/src/main/java/com/fastsun/platform/core/gateway/configurer/SecurityConfigurer.java`

```java
add("/web/*/*");
```

## 六、应用部署时的URL设置

在应用部署时，系统会自动设置 Web 和 H5 的访问地址。

### 6.1 独立部署模式

**文件：** `BackendSingleDeployService.java`

```java
// 设置H5访问地址
lcAppDTO.setH5Url(single + ":" + freePort + "/" + lcAppDTO.getCode() + "/h5/index.html");

// 设置Web访问地址
lcAppDTO.setWebUrl(single + ":" + freePort + "/" + lcAppDTO.getCode() + "/web/index.html");
```

**示例：**
```
Web URL: http://192.168.3.252:8080/hnsh/web/index.html
H5 URL:  http://192.168.3.252:8080/hnsh/h5/index.html
```

### 6.2 微服务部署模式

**文件：** `BackendMicroNacosDelopyService.java`

```java
lcAppDTO.setH5Url(appPrefix + "/" + lcAppDTO.getCode() + "/h5/index.html");
lcAppDTO.setWebUrl(appPrefix + "/" + lcAppDTO.getCode() + "/web/index.html");
```

## 八、常见问题

### 8.1 静态资源访问404

**可能原因：**
1. 静态文件未正确部署到指定目录
2. 应用编码（appCode）与实际目录名称不匹配
3. 文件路径权限问题

**解决方法：**
```bash
# 检查文件是否存在
ls -la /opt/lowcode/0/core/hnsh/dist/dist_web/index.html

# 检查文件权限
chmod -R 755 /opt/lowcode/0/core/hnsh/dist/
```

### 8.2 Windows环境路径问题

**说明：** 
代码已自动处理 Windows 和 Linux 的路径差异：
- Linux：`file:/opt/lowcode/...`
- Windows：`file:///D:/lowcode/...`

### 8.3 前端路由刷新404

**原因：** 
使用 Hash 路由（`#/xxx`）不会出现此问题。如果使用 History 模式，需要配置 Nginx 将所有请求转发到 `index.html`。

**当前方案：** 
框架使用 Hash 路由，无需额外配置。

### 8.4 H5端访问提示无权限（重要）

**现象：**
访问 `http://localhost:10222/hnsh/h5/index.html` 时提示无权限或需要登录。

**原因：**
**框架默认只将 `/web/**` 加入白名单，`/h5/**` 不在白名单中。**

这是框架的有意设计：
- H5端主要面向微信生态（企业微信、公众号）
- 依赖微信 OAuth2 授权机制自动登录
- 理论上不需要公开访问登录页

**解决方法：**
如需开放H5端访问（开发调试、降级登录等场景），需手动添加白名单配置：

1. **fastsun-base/src/main/java/com/fastsun/platform/core/security/SecurityConfigurer.java**
```java
add("/web/*/**");
add("/web/**");
// 添加H5端白名单（根据需要选择）
add("/h5/index.html");     // 仅登录页
add("/h5/static/**");      // 静态资源
// 或者完全放开（不推荐）
// add("/h5/**");
```

2. **fastsun-gateway/src/main/java/com/fastsun/platform/core/gateway/configurer/SecurityConfigurer.java**
```java
add("/web/*/*");
// 添加H5端白名单
add("/h5/index.html");
add("/h5/static/**");
```

**注意：** 
- 修改后需要重启应用才能生效
- 建议只开放必要的资源，不要完全放开 `/h5/**`
- API接口仍然受保护，不会因为静态资源公开而存在安全风险

## 九、总结

### 9.1 架构特点

1. **前后端分离**：前端静态资源与后端API完全分离
2. **多应用隔离**：每个应用有独立的静态资源目录
3. **跨平台支持**：自动适配 Windows 和 Linux 系统
4. **灵活配置**：支持默认路径和应用自定义路径

### 9.2 技术要点

- 使用 Spring MVC 的 `ResourceHandler` 提供静态资源服务
- 通过 `WebMvcConfigurer` 接口配置资源映射规则
- 采用 Hash 路由避免前端路由刷新问题
- **Web端静态资源（`/web/**`）默认在白名单中，可匿名访问**
- **H5端静态资源（`/h5/**`）默认不在白名单中，需手动配置**

### 9.3 关键文件清单

| 文件路径 | 作用 |
|---------|------|
| `LowCodeWebMvcConfig.java` | Web端和H5端静态资源配置（硬编码路径） |
| `WebMvcConfig.java` | Web端和H5端静态资源配置（动态路径） |
| `LowcodeAppUtil.java` | 应用根路径计算工具类 |
| `BackendSingleDeployService.java` | 独立部署服务，设置访问URL |
| `BackendMicroNacosDelopyService.java` | 微服务部署服务，设置访问URL |
| `SecurityConfigurer.java` | 安全配置，将静态资源加入白名单 |
| `gen-bootstrap-single-xx.ftl` | 应用配置文件模板 |
